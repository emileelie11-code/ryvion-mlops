Part A

Get the environment right

Two things go wrong here and nowhere else: the wrong Python, and a virtualenv that predates the last dependency change. Both fail loudly rather than silently, which is by design.

1

Create the virtualenv on Python 3.11

Not 3.12 or newer. The package declares requires-python == 3.11.* and pip will refuse anything else — that refusal is the feature.

PowerShell, from the repo root

cd C:\Users\eastih\Downloads\ryvion-mlops
git checkout main
git pull

py -3.11 -m venv .venv
.venv\Scripts\Activate.ps1

Git Bash use source .venv/Scripts/activate instead.

2

Install the locked environment, then the package

The lockfile pins 150-odd packages to exact versions — the same ones CI validated. The second command installs this repo's own code without letting pip renegotiate any of those versions.

python -m pip install --upgrade pip
python -m pip install -r environments/dev.lock.txt
python -m pip install -e . --no-deps
CheckpointNo resolver errors. If pip starts downgrading things, you skipped --no-deps.
3

Run the gate that every pull request runs

These are the two commands both CI systems execute. Nothing else in this runbook matters if these fail.

python -m flake8 .
python -m pytest

Expected

(flake8 prints nothing and exits 0)

156 passed, 2 warnings in 21.41s
Checkpoint156 passed — the README still says 150; it went stale when slice #18 merged. The number to trust is the one pytest prints.

Part B

Run the four-step pipeline

Validate → train → evaluate → register. These are the same four steps that will become cloud jobs in slices #7 and #8; running them here is the local rehearsal of that pipeline. Each one signals through its exit code, which is how a pipeline knows to stop.

4

Point MLflow at a database, then validate the data

The model registry needs a database-backed store — a plain file store has no registry. SQLite gives you one locally with no server. Set this once; every step below inherits it.

# PowerShell — keep this shell open for the rest of Part B
$env:MLFLOW_TRACKING_URI = "sqlite:///mlflow.db"

python -m automobile.entrypoints.validate

Expected

data: C:\Users\eastih\Downloads\ryvion-mlops\data\auto-mpg.csv
PASS  automobile-mpg data contract: 398 rows, 8 rules, no violations.
Checkpointexit 0 and 8 rules checked. Check with echo $LASTEXITCODE.
5

Train the model

Reads the seed CSV, fits the pipeline, logs the run and the model. Seconds, not minutes — the dataset is 398 rows.

python -m automobile.entrypoints.train

Expected — copy the run id, you need it twice

tracking uri:    sqlite:///mlflow.db
experiment:      automobile-mpg
run id:          71b2a2b888704baf908d19e378ea5b93
model uri:       models:/m-49055c6012d54e69ae547e61f344e9ea
train metrics:   {'mse': 11.663944908970032, 'rmse': 3.415251807549486, ...}
test metrics:    {'mse': 8.195643426571698, 'rmse': 2.862803420874667, ...}
CheckpointYour run id will differ. test mse should be 8.1956… — the split is seeded, so this number is reproducible.
6

Evaluate, then register

Nothing is registered yet, so the gate has no incumbent to beat and promotes by default — the first model ever trained becomes the baseline. Substitute your own run id.

python -m automobile.entrypoints.evaluate --run-id <YOUR_RUN_ID>
python -m automobile.entrypoints.register --run-id <YOUR_RUN_ID>

Expected

incumbent:       none registered yet
policy:          test_mse minimise, margin 0.0
decision:        promote (no-incumbent)

Successfully registered model 'automobile-mpg'.
Created version '1' of model 'automobile-mpg'.
new version:      1
CheckpointBoth exit 0, and version 1 exists. Browse it with mlflow ui --backend-store-uri sqlite:///mlflow.db.

Part C

Prove the gates actually stop things

This is the part worth your attention. A pipeline that passes when everything is fine proves very little — what matters is that it refuses when something is wrong. Both tests below are meant to fail, and a zero exit code here would be the bug.

7

Train a deliberately bad model and watch the gate reject it

Starve it of training data by holding back 90% for testing. The model gets measurably worse, and the gate compares it against the version you just registered.

python -m automobile.entrypoints.train --test-size 0.9
python -m automobile.entrypoints.evaluate --run-id <THE_NEW_RUN_ID>

Expected — this failure is the pass condition

decision:        reject (below-threshold)
why:             reject: test_mse=16.425971664863873 misses the
                 required 8.195643426571698 (incumbent 8.195643426571698)
Checkpointexit 1. In a pipeline that non-zero exit is what stops the run before anything gets registered.
8

Try to register the rejected model anyway

Belt and braces. Even if someone bypasses the exit code, the register step reads the gate's verdict off the run itself and refuses. This is the property the whole quality-gate slice exists to guarantee.

python -m automobile.entrypoints.register --run-id <THE_BAD_RUN_ID>

Expected

refusing to register run 19b06623d6864954b0bf9df5aa2a25e3:
automobile.gate.decision is reject. Only a candidate the
quality gate promoted is registered.
Checkpointexit 1, and the registry still holds exactly one version, not two.
9

Corrupt the data and watch the contract catch it

Copy the seed CSV, break something in the copy, and point the validator at it. The contract names the rule that failed and the rows that caused it.

Copy-Item data\auto-mpg.csv $env:TEMP\broken.csv
# open it and change one mpg value to -1, then:
python -m automobile.entrypoints.validate --data $env:TEMP\broken.csv
Checkpointexit 1, and the message names mpg_is_positive plus the offending row number.

Part D

Build and run the serving container

The hand-built image — the one students construct themselves and later deploy to Kubernetes. It needs a container engine and nothing else: no cloud account, no registry login. This is the artifact that 13 hours of the course depends on.

10

Export the model beside the Dockerfile

The image bakes in a model rather than fetching one. serving/model/ is gitignored — the repo versions code and seed data, not artifacts. Use the model uri printed by your good training run in step 5.

mlflow artifacts download --artifact-uri models:/<YOUR_MODEL_ID> --dst-path serving/model
Checkpointserving/model/ contains MLmodel, model.pkl and a code/ directory. That code/ folder is slice #18 — the model now carries its own source and loads without the repo.
11

Build and start it

Build from the repo root, not from serving/ — the Dockerfile needs the requirements manifest that lives above it. First build takes a few minutes; it is ~1.4 GB.

docker build -f serving/Dockerfile -t ryvion-mlops-serving:local .
docker run -d --name ryvion --rm -p 8000:8000 ryvion-mlops-serving:local
docker ps
CheckpointStatus reaches (healthy) after ~30s — the image has its own HEALTHCHECK, so Docker is testing it for you.
12

Call it

Three requests: a normal one, one where horsepower is unknown, and one that is malformed on purpose.

PowerShell trap

In PowerShell, curl is an alias for Invoke-WebRequest and will not understand -X or -d. Type curl.exe explicitly, as below, or use Git Bash.

curl.exe -s localhost:8000/healthz
curl.exe -s localhost:8000/readyz

# put the JSON in a variable — quoting it inline is where this goes wrong
$body = '{"records":[{"cylinders":8,"displacement":307.0,"horsepower":130.0,"weight":3504,"acceleration":12.0,"model year":70,"origin":1,"car name":"chevrolet chevelle malibu"}]}'

curl.exe -s -X POST localhost:8000/predict -H "Content-Type: application/json" -d $body

Expected

{"status":"ok"}
{"status":"ready","model_uri":"/app/serving/model"}
{"predictions":[14.975242297915628]}

Now send the same record with "horsepower": null, and then one with columns missing:

horsepower null   -> {"predictions":[15.294602119006564]}
missing columns   -> HTTP 422 "record 0 is missing required columns
                     'displacement', 'weight', … ; see GET /schema."
CheckpointThe null case is the interesting one: a different prediction, because the imputer inside the model substituted the mean it learned during training. The service itself knows nothing about that.

Reference

When something goes wrong

  • “No module named numpy” — you are running the system Python, not the virtualenv. Re-activate it, or call .venv\Scripts\python.exe directly.
  • “No module named pandera” — your virtualenv predates the data-contract slice. Re-run pip install -r environments/dev.lock.txt. This failing loudly is the lockfile working.
  • Registry errors mentioning a file store — MLFLOW_TRACKING_URI is unset in this shell. It does not persist across terminals.
  • curl rejects -X or -d — PowerShell's alias. Use curl.exe.
  • Port 8000 already in use — docker rm -f ryvion, or map a different port with -p 8001:8000.
  • readyz returns 503 — the container is up but no model loaded. You most likely skipped step 10, or built before exporting the model.
